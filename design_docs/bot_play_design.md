# 本地人机试玩与训练隔离

更新日期：2026-10-26。

## 1. 目标和入口

在长时间 RL 训练继续运行时，用已完成的模型快照和真人对局，保留现有的手牌实体、拖动、分组、吃碰杠胡过、计时和普通结算合同。

```powershell
# 仓库根目录；不要停掉训练，也不需要使用训练虚拟环境。
.\.venv\Scripts\python.exe -m multiplayer.bot_play --port 8772
```

访问 [本地人机试玩](http://127.0.0.1:8772)，填写用户名、房间名和密码创建房间，点击右上角房主设置，再点击开始本局。创建时自动安排房主和三位 Bot；有可用冻结 RL 时默认 RL 速胡、RL 做大、RL 稳守，否则默认三种无需模型的启发式风格。每席的策略只在首次开局前或安排下一局时修改。

已开放现有全部 25 个配置，菜单分为八类：

| 类型 | 配置名 | 模型 |
| --- | --- | --- |
| 基础 | `tsumogiri`、`random`、`win-random` | 不需要 |
| 数学 | `math` | 不需要 |
| 搜索 | `search` | 不需要；现有 t3 出牌截断搜索 |
| 启发式风格 | `fast`、`big`、`defensive`、`blocking` | 不需要 |
| 模仿学习 | `nn-fast` 等四种风格 | 独立 NN `.npz` |
| 强化学习 | `rl-fast` 等四种风格 | 沿用冻结 RL `.npz` |
| 精确 CFR | `cfr-fast` 等四种风格 | 精确平均策略 `.json.gz` |
| 抽象 CFR | `acfr-fast` 等四种风格 | 抽象平均策略 `.json.gz` |

缺少、损坏或不兼容的模型只禁用对应类型，不阻止数学/搜索/启发式策略开局；菜单保留禁用项和原因，不把“没加载到模型”静默伪装成该学习策略。已加载 CFR 在未命中信息集时仍按其原策略合同回退，并在赛后如实标记。

房主可移出候场 Bot，邀请真人，再安排四席。一个试玩服务同时只开一个房间、最多三个 Bot，总人数仍最多十人；Bot 不需要浏览器窗口。房主可观战。纯真人入口 `multiplayer.web` 保留，不自动开启策略 Bot。旧存档服务和固定对手开发者入口已移除；当前牌桌与真人命令合同继续复用。

每局开局前可选择普通或血战模式、一炮多响和计时，本局中锁定，结算后点“下一局”即可修改并在确认开局时应用。最终结算直接提供“查看牌山”，安排下一局期间仍能回看，确认新开局后关闭。血战中已胡席位不再产生 Bot 决策，UI 提供即时结算和退出状态。现有观察编码、模型与训练流程保持普通模式合同：数学、搜索、规则风格和 NN/RL 会因血战计分合同走现有合法降级路径（有胡接受，其余过牌或摸切），不能把这视为原模型在血战中推理；CFR 沿用各自查表/未命中处理，也没有血战强度结论。房主选择血战时会看到提示。规则详见 [血战设计](blood_battle_design.md)。

可选依赖为 `multiplayer/requirements-bot.txt`，只增加 NumPy，不增加 Torch。当前开发环境已具备，不需要为试玩修改 `.venv-bot`。服务只监听 `127.0.0.1`，不开放公网，不替代 Access。

## 2. 模型与训练进程隔离

- 不修改 `simulator/`、`calculator_base/`、`fan_calculator/`、`bots/`、`arena/`、`training/` 的 Python 源码，不改变训练源码指纹。
- 不终止、重启、调度训练进程，不更改其优先级、环境、GPU 或输出目录。
- **默认不更新 RL。** 省略 `--model` 时只读取私有 `multiplayer/.runtime/rl-selection.json` 中记录的冻结副本，并验证 SHA；没有记录就不启用 RL。记录损坏不自动改用新训练产物。训练完成后已按本次更新请求，从第 42 轮切换到开发验证选中的第 68 轮；最新完成批为第 71 轮，二者不能混淆。
- 只有显式传入 `--model` 才选择/更新 RL：目录参数选取 `snapshots/ppo-数字.npz` 中编号最大的已完成文件，排除 `.partial.npz`。`latest.npz` 参数仅作为目录选择的便捷写法，**不打开该别名**。
- 不打开 RL 训练持续覆盖的 `latest.npz`、`policy.npz`、训练状态 JSON 或 `.pt`。如需最佳而非最新策略，由用户指定对应编号快照，不读可变别名推测。
- 启动时把选中的完成快照复制到忽略的 `multiplayer/.runtime/play-models/<随机目录>/policy.npz`，校验归档、合同与 SHA-256。之后只加载这份私有副本，整次服务运行不热更新。
- NPZ 复制读取上限为 16 MiB，CFR 压缩策略表为 128 MiB；缓存不得位于来源模型目录内。NPZ 使用现有 `allow_pickle=False` 加载器，CFR 使用既有归档和合同校验，不读 `resume` 检查点。
- NN、精确 CFR、抽象 CFR 分别复制当前已有的 `.data/models/p4-v1/policy.npz`、`.data/models/cfr-mahjong/policy.json.gz`、`.data/models/cfr-abstract-v1/policy.json.gz`，不共用 RL 文件。对应训练当前未运行；以后若并行训练这些类型，应使用下面参数指向独立完成副本。
- 四类模型的可用状态、冻结迭代号（适用时）和 SHA 在房主设置中可见。所有模型在启动时预热，整局不热更新。重启服务仍沿用原 RL；训练完成后主动传 `--model` 才更新。

```powershell
# 明确要求更新 RL 时才运行（先停止旧试玩服务）。本次使用验证选中的第 68 轮。
.\.venv\Scripts\python.exe -m multiplayer.bot_play --port 8772 --model .data/models/rl-3h/snapshots/ppo-0068.npz
# 若传 .data/models/rl-3h 目录，则选择最新完成批，不自动按验证报告挑选。
# 可分别指定其他已完成模型。
# --nn-model <file.npz> --cfr-model <policy.json.gz> --acfr-model <policy.json.gz>
# 完全不读模型：基础、数学、搜索、启发式风格仍可玩。
.\.venv\Scripts\python.exe -m multiplayer.bot_play --port 8773 --no-models
```

Windows 特别说明：共享删除并不能保证 Python `os.replace` 可以覆盖打开的目标文件，已在本机临时文件测试中复现，因此不采用“短暂打开训练别名就一定没影响”的假设。改为读取训练器生成后不再覆盖的编号快照。[CPython 文件替换限制说明](https://bugs.python.org/issue46003)

## 3. 资源和超时

- 独立一个 CPU 推理进程，三个 Bot 串行复用；不启动 Arena 的四进程池，不启动训练器，不导入 Torch/CUDA。
- 服务和推理子进程只降低自身优先级；推理子进程在导入 NumPy 前把常见 BLAS/OMP 线程数限制为 1，并隐藏 CUDA。
- 默认计算预算 500 ms，可用 `--compute-ms` 设置 10～1000 ms；实际预算不超过该操作窗口剩余时间，预留 30 ms。
- 策略合作式预算另留 20%、最多 100 ms 返回余量；硬上限不延长。以独立进程报告的实际计算完成时刻判断是否超算，避免 100 ms 服务轮询把按时完成误判为超时；落地仍用当前真实时间校验游戏窗口，不能通过旧时间绕过 t1～t4。
- 每个窗口约 0.4 秒可读停顿；这不是额外 t1/t2/t3/t4，也不刷新引擎计时。
- 所有真人命令、计时推进和 Bot 结果提交仍串行校验；耗时策略计算在进程外进行，房间锁不等待计算。
- 超过计算硬截止，即使结果已经迟到到达，也不使用。只终止本服务自己的推理子进程；本局后续使用默认过牌、摸切等合法保底。下一局由房主确认开局时重新准备策略进程。
- 模型内部也可能因编码预算不足返回对应启发式风格，不代表每一步都经过模型。赛后状态区分 `model`、`fallback`、`hard_rule`、`baseline`、`forced` 和运行器 `default`，不把保底宣称为模型决策。
- 数学/搜索/启发式状态单独命名，例如 `math`、`search:budget_limited`、`style`；CFR 使用 `cfr:average`、`cfr:unseen-style`、`acfr:average`、`acfr:unseen-rule` 等原策略状态，不全部算作基线或模型命中。

**同一台电脑仍共享 CPU、内存和磁盘，不能承诺训练速度完全不变。** 目标是不干预训练状态并控制额外资源，不是零开销。试玩闲置在大厅或真人不操作时不会无限排队计算。

## 4. 控制权和可见信息

```text
真人 UI -> 原 LiveRooms / LocalRooms 命令 -> GameState
明确配置的 Bot 席 -> bots.DecisionDriver -> 现有 GameState 命令
                       |
                       +-> 脱离状态的观察和候选 -> 单 CPU 推理进程
```

- 真人不经过 Bot 驱动，不自动替真人过掉胡杠提示、选择同值实体牌或整理手牌。
- Bot 只拿本人玩家观察和稳定合法候选，使用现有可见历史；不拿其他暗手或未来牌山顺序。推理子进程不持有 GameState。
- 精确 CFR 在试玩工厂绑定真实绝对座位，不能把四席都当 seat 0。每席、每风格、每局有独立策略实例和随机状态；只共享只读模型缓存。
- Bot 成员没有浏览器登录凭证，只能被房主在开局前配置。缺人不能偷偷把真人席改成策略 Bot。
- 请求关联牌局对象、轮次、窗口、控制权和手牌语义。暂停、换局、关房或窗口失效后，旧结果不能落地；别的真人正常整理自己的牌不使 Bot 当前决策无故失效。
- Bot 不是“离线真人”：不参与人类 socket 断线判断，不触发 300 秒等待或全服故障归因。真人仍使用原连接、暂停和托管规则。
- 进行中不广播 Bot 的候选、响应意图、具体决策状态或计数；只显示统一 Bot 身份。完整统计只在赛后开放，避免借此推断谁能吃碰杠胡。
- 有 t1 时，**每一家**弃牌之后仍等满 t1；无 t1 时，Bot 可提交自己的过，但仍等待所有需要响应的真人手动操作。
- t2 的不超过五种展示/超过五种手选，以及玩家明确选择实体牌，继续使用原路径。Bot 自己使用现有完整候选适配，不改变 UI 合同。
- 暗杠、加杠、抢杠和 t4 恢复剩余 t3 均调用既有规则；普通结算、牌山赛后查看、局间换人和座位分数继承沿用原流程。此入口不做存档恢复，关服重置。
