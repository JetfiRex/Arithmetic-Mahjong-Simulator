# CFR / MCCFR 独立实验首版

## 1. 目标与状态

提供可独立训练、恢复和对局的表格 outcome-sampling MCCFR 首版，沿用 `Bot.act(observation, legal_actions)`。它与 PPO 是独立的离线学习路线，当前不进入真人房间，也不在真人对局中自动更新。

- ✅ 遗憾匹配、完整轨迹 outcome sampling、反事实遗憾与平均策略的重要性权重。
- ✅ 独立三张牌 Kuhn poker 环境和精确最佳回应审计器；它是验证算法的小博弈，没有缩小或更改正式麻将牌池。
- ✅ 完整麻将规则的训练适配、仅可见信息的信息集、额外的自家决策记忆、四种终局风格目标。
- ✅ 冻结平均策略 `CfrBot`、严格模型合同、未知信息集的明确回退、独立 Arena 入口。
- ✅ CPU 训练入口、局级原子更新、gzip JSON 检查点、RNG 恢复、时长和表容量限制。
- ✅ 24 项轻量正确性检查；当前 RL 运行期间仅用低优先级、单核检查进程，最后一次耗时约 1.13 秒，未启动 GPU 或完整麻将采样任务。
- ✅ 用户完成 5,337 局完整麻将训练；已读取检查点并完成 128 局冻结独立对照，表命中为 0%，详见 [实际评测](../test_docs/cfr_1h_evaluation.md)。
- ✅ 后续新增固定分类器/合法规则的独立抽象版本，已确认重复更新与新局表命中，并做短计时检查，见第 8 节。
- ❌ 收益/风格改善、长时间 Kuhn 收敛、全面限时场景、Deep CFR、在线适应、房间接入与真人陪玩验收。

## 3. 算法合同

实现依据 [MCCFR 原论文](https://www.cs.cmu.edu/~waugh/publications/nips09b.pdf)。每条完整轨迹选择一个 update player；该玩家用 `beta = (1-epsilon) * sigma + epsilon / |A|` 探索，其他玩家按当前遗憾匹配策略 `sigma` 采样。整条轨迹期间策略表保持冻结，只有正常终局后才提交更新。

设到当前节点的己方、其他方含机会、实际采样到达概率分别为 `pi_i`、`pi_-i`、`q`。反向返回的后缀估计已经乘了后续目标/行为概率比；当前采中动作 `j` 的估计为 `child / beta[j]`，未采中动作估计为零。节点值为 `sigma[j] * child / beta[j]`，遗憾增量再乘 `pi_-i / q`。采中的目标概率为零时，仍须先更新该动作的反事实遗憾，再把向前返回的节点估计置零。

平均策略累计使用 `pi_i * sigma[a] / q`，不是访问次数，也不是最后一轮的策略。冻结对局默认随机采样累计平均策略；直接取 argmax 会改变策略，不能附带相同的平均策略解释。

概率和权重使用对数表示。每个信息集的遗憾向量与策略累计向量分别保存数值及对数尺度，统一正比例缩放不改变遗憾匹配或平均策略归一化。没有裁剪大额筹码、遗憾、重要性权重，也没有将负遗憾清零后累计成 CFR+。有限精度计算仍有舍入误差。

超时、截断、非法终局或容量不足均不会提交半条轨迹；采样 RNG 回退到该轨迹前，状态对象丢弃。单人或多人单路径采样不需要复制整棵引擎分支；external sampling 和分支复制是后续独立能力。

## 4. 麻将信息集与机会采样

信息 key 包含绝对策略座位、自己的风格类型、完整玩家观察、规范化合法候选及自己的此前决策链。观察仍由现有 `Observation` 投影提供；计时、UUID 和动作 ID 不进入 key。

自家决策链累计此前的观察/候选与所选动作，因此不会仅依赖公开牌河而遗忘自己的过牌、私有摸牌或此前知道的合法菜单。实际引擎仍处理同时响应，后行动者的 key 看不到先提交者的未公开承诺。散列用来索引完整信息，不把多个相似牌型主动合并为一个桶。

训练只接受新建、快速模式的独立 Arena，拒绝接管现有状态或计时/真人会话。整个多重集牌山在根部按原牌池洗牌采样，真实值序概率为 `prod(count!) / total!`；之后摸牌是在该牌山条件下的确定转移，不重复计机会概率。训练器还在根部均匀采样庄家和各席私有风格类型，并计入其真实采样概率。随机过程使用可恢复的伪随机种子流。

合法 HU 固定接受、唯一合法动作固定执行；这是明确版本化的策略限制，训练和部署一致。其余具体候选完整保留，不用真人 UI 的候选展示上限裁剪训练动作。

## 5. 风格与策略规模

风格为速胡 `fast`、做大 `big`、稳守 `defensive`、高牵制 `blocking`。终局效用沿用 PPO 的 `terminal-style-utility-v1`：实际净筹码除以 32，再加真实胡牌/摸牌数/基础赔付/点炮/其他胡牌/流局的风格项。已有专项检查与 PPO 奖励结果一致。

四个类型独立采样，训练报告记录实际类型数量，不保证短批次恰好均衡。表格首版的稳守和高牵制对应离散端点，没有加入任意连续牵制插值。

**完整麻将的信息集数量非常大。** 精确可见历史 key 即使数学上保持了记忆，也可能在新牌局中几乎不复用。首版先验证算法与端到端合同；不能承诺跑几千局就能得到好策略。后续需要根据实际命中率决定信息/动作抽象、函数逼近或 Deep CFR，而不能把原版表格的动作变化当成已学会麻将。

`CfrBot` 对未见信息集默认调用对应 `StyleBot`，诊断为 `unseen-style`；也支持 `unseen="uniform"`，用于检查纯表格平均策略。回退会改变实际部署策略，评测必须报告其比例。高收益但平均策略命中率接近零，只能说明混合策略主要在使用回退。

四人带私有风格效用的游戏一般也不再是筹码意义的零和目标；不宣称两人零和的均衡收敛保证适用于此实验。精确 exploitability 只在小型 Kuhn 环境计算，不伪造完整麻将的 exploitability 数字。

## 6. 文件与恢复

```text
bots/
  cfr_policy.py       可见信息 key、自家记忆、冻结策略文件校验
  cfr_bot.py          平均策略查表、合法 HU、未知局面/预算回退
training/cfr/
  core.py             MCCFR 采样与原子遗憾/平均策略更新
  kuhn.py             小型已知博弈与精确最佳回应审计
  mahjong.py          原麻将引擎适配与四维风格效用
  storage.py          检查点与冻结平均策略导出
  train.py            独立 CPU 训练/恢复/容量与时长限制
  play.py             独立 Arena 调度、模型 SHA 与命中/回退统计
  configs/            Kuhn 与麻将配置
```

`resume.json.gz` 保存完整遗憾、平均累计、尺度、访问数、采样 RNG、下一更新座位及统计。每个 iteration 包含所有座位各一次 update-player 采样；麻将一轮为四个完整采样局，Kuhn 一轮为两个。停止在半个 iteration 也能准确恢复下一座位。

`Ctrl+C` 请求完成当前局后保存，避免在表更新和进度游标之间中断；训练时间限制同样在完整局边界生效。引擎单次调用内的超时是软检查，当前训练器不是面向真人请求的硬实时执行器。对局阶段继续由现有 Arena 工作进程执行硬预算。

checkpoint 先提交，之后从已提交表导出 `policy.json.gz`；恢复会重建策略别名。文件是有限大小、经校验的 gzip JSON，无 pickle。恢复要求原配置、源代码和规则合同一致；允许增加目标轮数、表容量，调整保存间隔和本次时长/软超时。

正常对局只读取冻结平均策略，不修改模型。`warmup()` 在实时决策窗口前加载；独立入口使用原 Arena 生命周期。直接复用同一 bot 跨局时，应明确调用 `reset()`；房间端的 bot 记忆存档尚未接入。
