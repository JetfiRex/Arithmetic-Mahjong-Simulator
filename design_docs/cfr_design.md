# CFR 设计

更新日期：2026-10-27。

## 目标与边界

提供可离线训练、恢复及冻结对局的四种风格策略：速胡、做大、稳守、牵制。它沿用原抽象 CFR 的近似 outcome-sampling 遗憾学习算法，“CFR”是本项目的显示名称。本次改名不改变算法、牌局规则或既有模型权重。

- ✅ 使用 `Bot.act(observation, legal_actions)`，只读玩家可见信息。
- ✅ 本地人机菜单提供四种风格，保持真人拖牌排序、吃碰杠胡过和计时流程。
- ✅ 固定分类器、有限状态桶、五种合法选牌计划、共享策略和完整局更新。
- ✅ CPU 离线训练、独立输出、严格检查点校验和随机数恢复。
- ✅ 已移除精确历史版的 Bot、入口、Kuhn、专用训练代码、模型及评测。
- ❌ 在线适应、血战专用训练、稳定收益提升及真人风格体验尚未验收。

## 观察与状态

手牌和公开信息先转为固定向量。明牌保留张数，忽略旧弃牌排列和自家完整决策链；三位对手各保留最近一次真实弃牌。分类器校准后冻结，默认分别将手牌和公开信息映射到 32 类和 64 类。

状态键由四种风格、四种决策窗口、早中晚三档、手牌类别和公开类别构成，最多 `4 × 4 × 3 × 32 × 64 = 98,304` 桶。绝对座位、时钟、具体动作 ID、对手暗牌及未来牌山不进入状态键。相对座位仍区分，四个物理座位可共享同一风格的表项。

当前结构特征是固定启发式，没有在线求精确缺张；牌值代理和风险指标也不是保证番数或校准的点炮概率。

## 动作与学习

五种计划分别偏好推进、牌值、安全、牵制和均衡。每种计划从引擎给出的具体合法候选中选一个动作；训练学习计划概率，部署时再映射到具体候选。多种计划选择同一个动作时，其概率相加。唯一动作、合法胡牌以及五种计划完全一致的窗口直接执行，不建立学习节点。

每个完整训练局轮流更新一个物理玩家；四局完成一次四席更新轮换。同局反复访问相同桶时逐次累计。遗憾和平均策略使用缩放数值与重要性权重，整局未完成时回滚更新及采样 RNG。未见桶按对应风格规则回退，评测需区分真实命中和回退。

缩短记忆、跨座位共享和受限计划空间使它成为近似实验，不具有完整麻将的精确求解或均衡保证。终局风格奖励是筹码收益以外的额外偏好，四席风格效用之和也不必为零。

## 文件职责

```text
bots/
  abstract_cfr_bot.py                 冻结策略本体，保留原 Python 类名
  cfr_bot_helper/
    policy_common.py                 动作语义、规则合同及安全归档读写
    cfr_abstraction.py               固定分类器、特征和合法选牌计划
    abstract_policy.py               模型加载、缓存和严格合同校验
training/cfr_abstract/
  numeric.py                         稳定概率运算与缩放遗憾行
  checkpoint.py                      遗憾行及 RNG 的严格恢复
  environment.py                     四人麻将训练环境和终局风格效用
  game.py                            粗粒度决策及计划到引擎动作的绑定
  core.py                            共享桶的采样更新
  fit.py                             独立校准和冻结码本
  storage.py                         检查点与冻结策略导出
  train.py / play.py                 训练恢复与独立评测入口
```

内部 `acfr-*` 配置、`AbstractCfrBot`、`training.cfr_abstract`、模型格式及目录沿用旧标识，以兼容既有模型与命令。试玩继续使用 `--acfr-model`，现有命令保持兼容。

## 恢复和限时

检查点保存完整累计、访问数、下一更新玩家、RNG、码本摘要、配置和源码摘要；普通续训继续严格校验，不自动接受修改过的规则或源码。本次仅整理共用工具，现有 26,794 局训练目录经独立备份和等价性检查后迁移源码身份，冻结模型与码本保持原字节。

试玩始终只加载冻结导出，不读训练检查点、不在线更新。合作式预算与独立进程超时保底继续生效，迟到结果不提交到已经失效的操作窗口。规则和真人操作接口不因本次清理而改变。
