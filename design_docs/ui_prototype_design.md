# 单机牌桌与交互设计

当前入口为 `singleplayer`，由一位真人和三家 Bot 对局。`UI/static` 提供牌桌页面、动作交互和单机设置；`singleplayer/web.py` 提供本机 HTTP 接口，`singleplayer/runtime.py` 串行驱动真实 `GameState`。旧开发者局与单人试牌服务已移除。

## 页面与操作

- 主牌桌展示三家对手、各家弃牌、牌山剩余张数、阶段与本人可见的计时。
- 手牌带按 `[副露] [有序手牌]` 展示。每张手牌绑定稳定实体 ID，可切换牌面/数字显示，窄屏时横向滚动。
- 左键单选后点击“出牌”提交该实体 ID。吃法不超过五种时列出方案，超过五种时选择恰好三张实体牌并确认。
- 普通响应、自摸、三种杠、抢杠和过牌使用后端给出的合法动作，前端不重新判定规则。
- 未胡玩家在 t1～t4 均可拖动排序；拖动显示插入位置，失败不产生部分修改，也不改变计时或已提交行动。手动吃牌高亮在拖动后保留原实体。
- 血战已胡玩家手牌只读。结算弹窗显示实际胡法、番种与得分，血战中可查看即时胡牌记录。

实体选牌和拖动规则见 [手牌身份、排序与动作选牌](hand_ordering_design.md)。

## 设置与局间流程

启动时打开设置，选择普通/血战模式、一炮多响、三家 Bot 策略和 t1～t4 计时。默认 t1/t2/t4 各 5 秒，t3 为 30 秒，可单独或全部关闭。本局开始后锁定配置。

结算进入 `REVIEWING`，点击下一局进入 `ARRANGING`；此时可修改配置并继续查看刚结束一局的牌山。确认开局后才发新牌，保留累计分数并关闭旧牌山查询。进行中不公开未来牌序。单机入口不开放手牌/牌山编辑、预置试牌场景或自动存档恢复。

## 请求与状态一致性

`GET /api/state` 返回经过过滤的真人视图，另含 `table`、`bot_play` 和 `ui` 信息。`ui.hand_ordering_allowed` 表示当前拖动权限。

`POST /api/action` 使用 `instance_id`、`command_id`、本局 `round_id` 以及对应动作的版本/窗口标识。出牌和移动等涉及本人手牌的操作校验 `hand_revision`；出牌、自摸、杠、过校验 turn window，吃牌与响应分别校验 detail/window ID。移动参数为 `tile_id` 和 `index`。

服务端在牌桌锁内串行处理请求、Bot 结果和超时，不依赖浏览器轮询推进计时。重复成功命令不会重复执行；旧请求返回错误及最新状态。前端拒绝旧 revision 覆盖新状态，保留未受本人手牌变化影响的拖动。

## 本机与桌面入口

浏览器入口仅接受本机页面操作。Windows 桌面版通过 Qt WebEngine 在独立窗口内展示同一牌桌，关闭窗口时回收本机服务和 Bot 子进程，详见 [Windows 发布说明](../windows/README.md)。

运行层与 HTTP 测试见 `singleplayer/test/test_singleplayer.py`；`singleplayer/desktop.py` 的发布自检及 `singleplayer/window_check.py` 检查静态资源、设置、手牌排序、真人出牌、Bot 轮转与完整退出。
